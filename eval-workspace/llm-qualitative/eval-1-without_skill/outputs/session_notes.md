# session_notes — 把带公式的 Markdown 转成公众号可粘贴 HTML

## 1. 交付物

| 文件 | 说明 |
|---|---|
| `convert.py` | 转换脚本（无第三方依赖，Python 3 标准库） |
| `formulas_and_tables.html` | 产物。浏览器打开 → 全选 → 复制 → 粘贴到 mp.weixin.qq.com 编辑器 |
| `session_notes.md` | 本文件 |

复现命令：

```
PYTHONIOENCODING=utf-8 python convert.py <input.md> <output.html>
```

脚本自带自检，运行后打印统计与风险项（本次：残留 LaTeX 反斜杠 0、残留 `$` 0、风险项无）。

## 2. 我做了什么

1. 读源文件，确认它包含四类"微信容易翻车"的东西：**行间 LaTeX 公式**、**行内 LaTeX**、**表格**、**`> [!KEY]` / `> [!SUCCESS]` 提示块**，另外 front matter 里还有 `toc: always`（要求目录）、`theme`、`digest`。
2. 写了一个单文件转换器：解析 front matter → 分块（标题/段落/公式/表格/提示块/列表/分隔线）→ 渲染成**全内联样式**的 HTML。
3. 自己写了一个 LaTeX 子集解析器（不依赖 MathJax/KaTeX，见第 4 节）。
4. 用无头 Edge 实际渲染验证：
   - 在 **320px 视口**（最窄的常见手机）量 `documentElement.scrollWidth = 305 < 320`，**无横向溢出**，表格和公式都正常折行；
   - 逐图检查了正文、表格、提示块、公式的实际外观，修掉了两个问题（见第 6 节）。

## 3. 我假设的"微信公众号"约束（这些假设决定了整个实现）

来自对公众号编辑器的经验认知，**没有实测过**（无登录环境）：

1. **粘贴只保留行内 `style`**，`<style>`/`<link>`/`class` 全部丢弃。
   → 所以产物里**没有任何 class、没有任何 style 块**，88 个标签每个都自带完整行内样式。脚本的 `audit()` 会扫描并报出违规写法。
2. **不支持 MathML / MathJax / KaTeX**，也不会执行脚本。
   → 公式只能"就地排版"，见第 4 节。
3. **base64 图片会被剥离**（图片必须传公众号自己的素材库，得到 `mmbiz.qpic.cn` 链接）。
   → 所以**不能**走"公式渲染成 PNG 再内嵌"这条常规路线——那条路要求用户手工上传几十张图片，正是用户想避免的。产物里 0 张图片。
4. **会剥离 `id`，正文内锚点跳转无效**。
   → 目录（`toc: always`）渲染成**无链接的纯文本导航**，而不是 a 标签。如果用户想要可跳转目录，公众号本身不支持，只能改用"图片目录"。
5. `position/float` 会错乱、部分高级 CSS 不支持 → 全部避开（`audit()` 里已列为检查项）。
6. 正文习惯：15–16px 字号、1.8 行高、`#3f3f3f` 深灰字、`letter-spacing` 0.5–1px。产物按这套取值。

## 4. 公式怎么处理的（核心）

**路线：Unicode 数学符号 + 行内样式排版，把公式"画"成文字。**

因为微信既不认 MathML 也不认 base64 图片，唯一能粘进去还是矢量/文字形式的选择就是这条路（135编辑器、秀米等排版工具做分式用的也是同一招）。

自己写了 `_Math` 解析器（约 150 行），支持：

| LaTeX | 渲染方式 |
|---|---|
| `\frac{a}{b}` | `display:inline-block` 上下堆叠 + `border-bottom` 当分数线 |
| `\sum_{i=1}^{n}`（行间） | `display:inline-block` 三行堆叠：上限 / ∑ / 下限（字号 .58em/1.5em/.58em） |
| `\sum_{i=1}^{n}`（行内） | 退化成 ∑ 右侧挂上下标 |
| `x^2`、`x_i` | `<sup>`/`<sub>` **外挂** `vertical-align:super/sub` 行内样式双保险（万一微信剥掉标签，样式还能兜住） |
| `\bar{x}` | `text-decoration:overline` |
| `\sqrt{x}` | `√` + `border-top` 上划线 |
| `\left( \right)`、`\big` 等 | 直接吞掉，只留括号本身 |
| 希腊字母、`\pm \times \le \ge \ne \approx \infty \partial \int \cdots` 等 70+ 符号 | Unicode 码位（± × ≤ ≥ ≠ ≈ ∞ ∂ ∫ ⋯） |
| `\text{}` `\mathrm{}` | 强制直立 |

其它细节：

- **变量字母自动斜体**，数字/运算符直立——这是数学排版惯例，也是让公式"看起来对"的关键。
- `\left(x_i - \bar{x}\right)^2` 里的 `)^2` 能正确把上标挂到右括号上（`atom_char` 把 `)`、`]`、`|` 标记为可挂载）。
- 未知命令**优雅降级**：去掉反斜杠输出直立文本，不抛异常、不丢内容（`math_html` 外层还有 try/except 兜底）。
- 行内公式用 `.96em`、行间用 `17px`，都用 `'Cambria Math','Times New Roman',Georgia,serif`；`white-space:nowrap` 防止分式被从中间断开。

## 5. 结构类内容的转换

- **表格**：`border-collapse:collapse` + 每个 `th/td` 内联边框；`table-layout:fixed` 由首行 `th` 的 `width` 定列宽（首列 24%，其余均分）。这样在 320px 手机上三列不会挤成一团。
- **`> [!KEY]` / `> [!SUCCESS]`**：GitHub alert 语法，转成左侧色条的提示块（关键=琥珀色，结论=绿色），标题与标签同名时只显示一次。
- **目录**：front matter 里 `toc: always`，生成"本文导读"卡片，01/02/03 与正文 H2 前的编号一致（编号在 `convert()` 里统一分配）。
- **标题层级**：H1→文章标题；H2→带左侧竖条+两位编号的章节标题；H3→无竖条小标题。
- **front matter 的 `digest`** 同时放进了 `<head>` 的 HTML 注释（发表时填"摘要"框照抄）**和**正文开头的导语段。

## 6. 验证中发现并修掉的问题

1. `[!SUCCESS] 结论` 一开始渲染成"结论 · 结论"（标签和标题撞名）→ 加了两者相同时不重复的判断。
2. 预览页原来是灰底 + 居中留白。全选复制时浏览器可能把 body 的背景色一起带进公众号 → 把 body 改成纯白零内边距，留白移进文章容器内部。

另外一个**假警报**记录在此：`--window-size=375` 截出来的图右侧被裁，看着像横向溢出，实际是无头 Edge 忽略了 `--window-size`（`window.innerWidth` 报 496），截图只是把 496 的布局裁到 375。改用 iframe 强制 320px 视口后量到 `scrollWidth 305 < 320`，确认没有溢出。

## 7. 我不确定的地方（按风险从高到低）

1. **`display:inline-block` + `display:block` 子元素（分式/求和堆叠）在微信编辑器里的存活率。**
   这是全篇最不确定的一点。我知道 135/秀米这类工具用同样手法且能通过粘贴存活，但**没法在未登录状态下实测**。万一微信把内层的 `display:block` 清掉，分式会塌成"1 n"一行两段。
   兜底方案：把两个 `$$...$$` 里的 `\frac{1}{n}` / `\frac{1}{n-1}` 手工改成 `1/n`、`1/(n-1)` 写法——只需改源文件第 15、23 行的两处公式，`\frac` 换成 `/` 并给分母加括号即可，其余不用动。
2. **`<sup>/<sub>` 或 `vertical-align` 被剥**。两个都写了（标签 + 样式），任一生效即可，全剥的概率低；若全剥，`s^2` 会显示成 `s2`。
3. **`table-layout:fixed`、`border-collapse`、`word-break:break-word` 在粘贴后的表格里的支持度**。表格本来就是微信粘贴时最容易变形的元素（列宽可能被重算）。最坏情况是列宽变化，内容仍完整。
4. **字号/行高的观感**：我按常见公众号正文取值（16px/1.8），但每个号的偏好不同，用户在编辑器里全选改字号即可，不影响公式（公式的字号是相对 em 的）。
5. **`text-align:justify`** 在中文里好看，但和行内公式混排时，公式前后的空隙可能被拉伸。截图里没看出问题，若用户不喜欢可全局删掉这个属性。
6. `theme: minimal` 这个 front matter 我**没有实现成主题系统**——只按一种克制风格（蓝灰配色）输出。用户没提出主题需求，我理解为"整体风格简洁"。
7. 目录没有做锚点跳转（原因见 3.4），如果用户明确要求"点目录能跳"，需要另想办法（公众号正文内不支持，只能做图片目录）。

## 8. 使用步骤

1. 双击 `formulas_and_tables.html`，浏览器里检查一遍。
2. `Ctrl+A` → `Ctrl+C`。
3. 打开 mp.weixin.qq.com 图文编辑器，`Ctrl+V` 粘进正文区。
4. 用编辑器里的**预览**功能，切到手机尺寸再确认一次公式和表格（这一步很重要，第 7.1 条的风险只能在这里验证）。
5. 标题、作者、摘要从文件开头的 HTML 注释里抄（或直接用 front matter）。
